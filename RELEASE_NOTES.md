# Release notes

This repository accompanies the paper *Bridging the Lay-to-Clinical Vocabulary Gap: Hybrid Retrieval with Semantic Knowledge Graph Linking for Symptom-to-Condition Search*. These notes record how the study reached its final form. Commit hashes refer to the project's git history; `GIT_HISTORY.md` lists them with dates.

## Phase 0: earlier versions (v0–v3)

The project began as a retrieval-augmented symptom assistant: BM25, MedCPT and a knowledge graph fused by reciprocal rank fusion, plus a recency signal. Its evaluation went through four versions. The audit in Phase 1 found problems that made those results unsuitable for publication:
- a paraphraser that rewrote its own output;
- MRR truncated to a shortlist;
- a date-dependent recency prior;
- substring symptom matching;
- a v2 test set that shared 58 of 82 rows with the retrieval index;
- a headline claim (rank fusion beats linear fusion) that did not replicate.

All of this is kept for the record (`src/`, top-level `results/`, `legacy/`).

## Phase 1: audit (`ad2f0ef`, tag `pre-rebuild-audit`)

- `RESEARCH_AUDIT.md` maps every historical result to the code and data that produced it.
- It reproduces the stored v3 results exactly and explains each discrepancy.
- It identifies the dataset's structure: every record is its condition's symptom set minus at most one symptom, so clinical queries are close to lookup.
- The research question was reframed around lay-language robustness.

## Phase 2: protocol and measurement pipeline (`2c1b9de`, `e265204`)

- **New package.** `src/hsr/` implements the v4 pipeline. A legacy mode reproduces the v3 per-query results with 0 differences.
- **Frozen protocol.** `PROTOCOL.md` and `configs/protocol.yaml` were committed before any tuning. They fix:
  - the data flow: development rows only in every index;
  - MedCPT's standard 64-token queries;
  - whole-word exact matching as the baseline;
  - a deterministic tie-break;
  - matched H1–H4 comparisons;
  - condition-clustered statistics with Holm correction;
  - stopping rules.

## Phase 3: development sweep (`85a730a`, `605a4b9`, `c2f885f`)

- **First sweep.** The v1.0 sweep selected β = 1, which reduced the fused system to the graph alone.
- **Amendment v1.1.** Made before any test lexicon existed, it restricted the fused system to 0 < β < 1.
- **Rerun.** The sweep was rerun from scratch and selected SapBERT, τ = 0.525, β = 0.85, α = 0.3, 64-token queries.
- An independent verifier re-derives every value (`experiments/02b_verify_selection.py`).
- The v1.0 outputs are kept in `legacy/` and at tag `dev-sweep-v1.0`.

## Phase 4: test lexicon and final evaluation (`ce96f94`, `c92e434`, `8d0a7c0`, `33bd63d`)

- **Overlap audit.** Of the 181 test records, 148 had been queried in earlier versions (`audit/`).
- **Lexicon B.** Generated by Gemini 1.5 Pro from a fixed prompt, then frozen by SHA-256.
- **Final evaluation.** Run once from a clean commit.
- **Result.** All four pre-specified comparisons are significant. Semantic linking raised MRR on complete lay descriptions from 0.444 to 0.746.

## Phase 5: diagnostics and disclosures (`dc57f6e`)

- **Condition names.** A post-hoc check excluded 39 queries whose lexicon B wording named a condition; the H1 gain became +0.315.
- **Latency.** Measured at 52 ms median per query against 12 ms for the hybrid, on an RTX 3050 laptop GPU.
- **Disclosures.** Every deviation is collected in `results/rebuild/FINAL_PAPER_DISCLOSURES.md`.

## Phase 6: paper and second test lexicon (`8a33114`, `e8f7042`)

- **Manuscript.** An IEEE-format manuscript was written from the committed results; its source is not part of this public repository.
- **Lexicon C.** A co-author wrote a lexicon by hand without seeing the other lexicons, the code or any results. It was frozen by hash and evaluated once with the unchanged system. It confirmed the primary results (H1 +0.328) and is reported alongside them.

## Phase 7: mock peer review and robustness checks (`9c349f4`)

A critical review prompted further post-hoc checks. Each reproduced the committed ranks exactly before running:
- **Untouched records.** On the 33 records never queried before, H1 is +0.415 (lexicon B) and +0.364 (lexicon C).
- **Two-way bootstrap.** Resampling conditions and phrasings leaves every interval above zero.
- **Tie bounds.** The graph-only scores depend on the tie rule. The paper therefore claims only that fusion removes that dependence.
- **Pool intervals.** Linear beats RRF on complete queries.
- **Truncation.** With untruncated MedCPT queries, H3 is +0.237.

## Phase 8: release packaging (this release)

- **Replication script.** `experiments/08_reproduce_paper.py` reproduces Tables II–IV and checks them against the published files; the result is exact in the pinned environment.
- **Latency option.** The latency script gained `--out`, so replications do not overwrite published timings.
- **Tidying.** Historical root-level scripts and drafts moved to `legacy/` (see `legacy/README.md`), and `requirements.txt` now pins the v4 environment.
- **Documentation and ignore rules.** README reproduction guide, `CITATION.cff`, and a `.gitignore` that versions every file under `results/rebuild/`.
